## Scope and compatibility

本次按现有管理端“同步上游 7 天窗口”能力扩展为账号级自动联动。API Key 没有账号外键，因此“下挂”明确为账号所属分组的全部未删除密钥，而非按 usage log 猜测归属。无分组不自动扩展到全部密钥。

仅清零旧周期的 `usage_7d` 并对齐 `window_7d_start`。若密钥已经通过既有惰性换窗进入新上游周期，保留已经产生的新周期用量，防止后台再次清除。累计总额度、5h/1d 窗口、密钥状态和有效期不变；既有手动清零、单次同步窗口功能语义不变。standard/simple 模式使用相同的密钥窗口数据，不改变余额和订阅计费路径。

## Observation and state machine

- 开关默认关闭，不触发任何新上游请求，也不代替上游配额刷新或自动用卡。
- 后台每分钟读取已经持久化的真实上游周窗口。来源包括 Codex、Anthropic、当前国产 Coding Plan provider 与 Grok billing 周窗口；不使用本地账号周限额的推算时间。
- 首次有效观测建立基线，不清零。关闭后再开启、身份或分组变化须使旧基线失效。
- 只有新鲜且时间向前推进的可信观察才可能触发。大于 24 小时的窗口推进用于排除倒计时漂移和普通时间纠偏；提前换窗还需额外的用量下降证据。单纯到达旧 reset_at 不表示已经发生真实上游重置。
- 同组多个账号开启时跳过该组并清除其基线；解除冲突后重新建立基线，避免追溯清零旧周期。

## Atomicity and caching

事务内通过 PostgreSQL advisory try-lock 序列化周期处理，重新读取来源账号与分组，写入基线并一次更新目标密钥的 7d 用量与窗口；失败回滚，不提前确认周期。扫描不持有账号行锁，避免与计费的 Key→Account 锁序冲突；重置前对目标 Key 使用 `FOR UPDATE NOWAIT`，遇到并发占用直接回滚、下分钟重试。事务设置 `lock_timeout=500ms`，对基线外键检查等隐式锁等待同样有界，避免与分组删除形成长时间锁等待。多实例不能对同一周期反复清零。

新增迁移 `249_upstream_api_key_7d_reset.sql` 创建独立小表与主键，给 outbox 增加可空列，不回填业务数据、不扫描历史用量、不收紧既有约束；普通事务内执行。DDL 仍需要短暂表锁，部署应观察 migration 时长。新函数/触发器只在开关旧值或新值为 true、或开启账号的分组关联变化时失效基线；Token 正常轮转不视为上游身份变更。稳定上游身份变化时同时清理本功能消费的旧周快照，要求新身份的首次真实观测仅建基线，不能拿旧身份快照重建后误清额度；普通 off/on 保留快照但清基线。应用回滚不删除新表/列或恢复历史 migration。

缓存失效在数据库提交后执行，复用现有持久 auth outbox 的 lease、retry 和二次清理机制，新增可空 `api_key_id` 同时触发 billing rate-limit 缓存删除。既有跨实例 auth 广播仍保留。重置不依赖 Redis 锁作为唯一幂等依据，Redis 故障不允许重放清零数据库计数。

滚动升级时必须先完成全部实例升级，再开启账号开关：旧版本 outbox worker 不认识 `api_key_id`，旧新混跑可能只完成 auth 失效、遗漏 billing 缓存删除。默认关闭的升级路径不产生这类新事件，旧版本现有事件兼容；回滚应用前应关闭开关并先等待新事件处理完毕。单应用容器原地替换不存在新旧 worker 并行消费窗口。

## Upstream merge

合并固定上游提交 `ba81c7fd758e425d67f856d601147ef0c5263d3f`，保留 fork 的 Prompt Audit/Guard 接线、强制二次验证、监控中心、请求体准入/趋势、在途预留和模型目录定制。

两处兼容流转发冲突采用上游共用结算闭包，同时把 fork 的 `RequestBodyBytes` 加入闭包，确保成功与有用量的中断路径都保留监控字段。上游新增管理员路由测试同步补齐 fork 独有 `AlwaysStepUpAuthMiddleware` 参数，不降低生产验证门禁。

## Validation boundary

本机采用低并行编译和定向测试，不运行全量 build/lint/Vitest。PostgreSQL/Redis 集成测试需要专用可丢弃环境；本机 Docker daemon 不可用，不能把未执行的集成测试标记为通过。生产数据库、配置和服务不在本次操作范围。
