## Why

管理员目前需要分别清零分组密钥的 7 天已用额度、手动同步上游账号的 7 天重置时间。上游自然换周或成功使用重置卡后，下游密钥仍可能停留在旧窗口。

## What Changes

- 账号编辑提供独立的 `auto_reset_api_keys_on_upstream_reset` 开关，默认关闭，与“自动使用重置卡”无关。
- 后台消费已持久化的真实上游周窗口快照；确认新周期后，原子清零相关密钥的 `usage_7d`，并将 `window_7d_start` 对齐为新的上游重置时间减去 7 天。
- 首次开启、重新开启只建立基线，不补偿清零。重复采样、过期快照和小幅时间纠偏不能重复重置。
- 密钥实际归属分组，不直接归属账号。仅作用于来源账号所属的非空分组；同组存在多个已开启来源账号时跳过该组，避免不同上游周期相互清零。
- 数据库持久化幂等状态，支持多实例，并在提交后失效鉴权和限额缓存。

## Non-goals

- 不改变额度上限、累计总额度 `quota_used`、5 小时/1 天用量、密钥状态和有效期。
- 不把账号的本地周限额周期当作真实上游重置。
- 不新增上游轮询请求、不消费额外重置卡、不新增账号与密钥的绑定关系。
- 不修改生产配置、开启 Prompt Guard blocking、部署、提交或推送。

## Capabilities

### New Capabilities

- `linked-api-key-7d-reset`：账号级开关、真实窗口观测、分组作用域、事务幂等与缓存收敛。

## Impact

- 账号 Extra 配置和管理保存边界。
- 独立后台服务及其启动、关闭生命周期。
- 持久化周期状态与密钥用量原子更新。
- 管理端账号编辑、中英文文案与专项测试。
- 同批上游同步目标固定为 `ba81c7fd758e425d67f856d601147ef0c5263d3f`（2026-10-27 获取，v0.2.18 后的 upstream/main）。
